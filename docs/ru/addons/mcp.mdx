<center><h1>Аддон MCP-сервера</h1></center>

*Позвольте AI-агенту для кода писать, проверять и запускать скрипты внутри игры.*

Аддон MCP (id `hollowengine-mcp`) запускает в работающей игре сервер [Model Context Protocol](https://modelcontextprotocol.io). Агенты вроде Claude Code, Codex или Cursor подключаются к нему и получают инструменты, доступные только запущенной игре: настоящий classpath с классами Minecraft, диагностику скриптов, живой мир и скриншоты.

:::advice
Аддон новый. Относитесь к тому, что пишет агент, как к черновику, и читайте скрипты перед запуском: у агента ровно тот доступ к командам, который вы ему дали.
:::

## Подключение агента

1. Установите `HollowEngineMcp-*.jar` и [аддон компилятора Kotlin](/docs/hollowengine/addons/compiler), запустите игру и откройте мир.
2. Выполните `/he mcp`. В чате появится, запущен ли сервер и его адрес, с кнопкой для каждого поддерживаемого клиента.
3. Нажмите кнопку своего агента. Подключение вместе с токеном копируется прямо в буфер обмена; оно никогда не попадает в чат или лог:

   | Кнопка | Копирует |
   | --- | --- |
   | **Claude Code** | Команду терминала, добавляющую сервер. |
   | **Codex** | Блок для `~/.codex/config.toml`. |
   | **JSON** | Запись `mcpServers` для Cursor и других клиентов, читающих такую. |
   | **Token** | Только токен доступа. |

4. Вставьте её в терминал или конфиг агента.

Копировать подключение может только хост локального мира, потому что сервер слушает на компьютере, где запущена игра.

## Настройка

`config/hollowengine-mcp.toml`:

| Ключ | По умолчанию | Значение |
| --- | --- | --- |
| `enabled` | включён на клиенте, выключен на выделенном сервере | Запускает сервер. |
| `port` | `25590` | Порт, на котором он слушает. Всегда привязан к `127.0.0.1`. |
| `token` | генерируется | Bearer-токен, который агенты шлют как `Authorization: Bearer <token>`. Очистите его и перезапустите, чтобы выпустить новый. |

Сервер доступен только с вашего компьютера, и каждый запрос требует токен. Не делитесь токеном и не коммитьте `hollowengine-mcp.toml`.

## Инструменты

| Инструмент | Что делает |
| --- | --- |
| `run_command` | Выполняет команду от лица хоста локального мира и возвращает её вывод. |
| `run_snippet` | Запускает короткий Kotlin-сниппет на клиенте или сервере, чтобы осмотреть живое состояние. |
| `script_diagnostics` | Компилирует `.kts` файл и сообщает об ошибках. |
| `symbol_search`, `symbol_source` | Ищут API движка по имени и читают его исходники. |
| `docs_search`, `docs_read` | Ищут и читают эту документацию, встроенную в аддон. |
| `screenshot` | Делает снимок игры: вид игрока, мир без интерфейса или вид из выбранной точки камеры. |

Отдельных инструментов для списка, компиляции и перезагрузки скриптов нет. Агент пользуется теми же командами, что и вы: `he scripting run`, `he scripting attach`, `reload`, поэтому всё, чему он научится, работает и для игроков. Серверным сниппетам нужен выделенный сервер или включённые читы у хоста.

## Как агентам велено работать

Вместе с подключением аддон отправляет рекомендации, чтобы агенты делали функции **файлами скриптов**, а не одноразовыми сниппетами:

- поведение одной сущности - в node-скрипте с `@file:Attach`, прикрепляемом через `he scripting attach`;
- логика мира - в node-скрипте или обработчике `.reload.kts`;
- предметы и блоки - в `.startup.kts`, применяется после перезапуска;
- сниппеты нужны, чтобы осматривать живое состояние, а не поставлять функцию.

Затем агент гоняет `script_diagnostics`, пока скрипт не станет чистым, запускает его командой и проверяет результат по состоянию игры. Названия клипов анимации проверяются через `he model entity` и `he model info`, а не угадываются.
