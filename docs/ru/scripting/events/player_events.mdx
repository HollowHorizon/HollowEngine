<center><h1>Игроки и взаимодействие с ними</h1></center>

*Действия связанные с игроками и тем, что они делают.*

![NPC](/docs/title-missing.webp)

## Жизненный цикл игрока

### При входе на сервер

```kotlin
@SubscribeEvent
fun onPlayerJoin(event: PlayerEvent.Join) {
    val player = event.player
}
```

- `event.player` (Player) - зашедший на сервер игрок.

### При выходе с сервера

```kotlin
@SubscribeEvent
fun onPlayerLeave(event: PlayerEvent.Leave) {
    val player = event.player
}
```

- `event.player` (Player) - вышедший с сервера игрок.

### При смене измерения

```kotlin
@SubscribeEvent
fun onPlayerChangeDimension(event: PlayerEvent.ChangeDimension) {
    val player = event.player
}
```

- `event.player` (Player) - перемещающийся игрок.
- `event.from` (ServerLevel) - измерение из которого игрок перемещается.
- `event.to` (ServerLevel) - измерение в которое игрок перемещается.

### При респавне

```kotlin
@SubscribeEvent
fun onPlayerRespawn(event: PlayerEvent.Respawn) {
    val player = event.player
}
```

- `event.player` (Player) - текущий игрок.
- `event.isReturnFromEnd` (Boolean) - игрок вернулся из энда. (игра это воспринимает как респавн)

### При клонировании

Это событие срабатывает незадолго до `PlayerEvent.Respawn`, в ней есть ещё данные прошлого объекта игрока. То есть если вам нужно восстановить какие-то данные игрока при смерти это нужно делать тут.

```kotlin
@SubscribeEvent
fun onPlayerClone(event: PlayerEvent.Clone) {
    val player = event.player
}
```

- `event.player` (Player) - текущий игрок.
- `event.oldPlayer` (Player) - игрок до смерти / перемещения.
- `event.wasDeath` (Boolean) - это была смерть или перемещение из энда.

:::advice
Если пережить смерть должны именно типизированные [`player.data`](/docs/hollowengine/scripting/npc/data), это событие вообще не нужно: `player.data` переносится автоматически. Это событие для всего остального, произвольного NBT или логики, привязанной к точному моменту передачи данных между двумя объектами игрока.
:::

## Действия игроков

### Ложится спать

```kotlin
@SubscribeEvent
fun onPlayerSleep(event: PlayerEvent.SleepInBed) {
    val player = event.player
}
```

- `event.player` (Player) - текущий игрок.
- `event.problem` (BedSleepingProblem?) - причина, по которой игрок не может уснуть, если есть. (можно также поменять на свою причину)
- `event.pos` (BlockPos) - координаты блока кровати, по которому нажал игрок.

### Просыпается

```kotlin
@SubscribeEvent
fun onPlayerWakeup(event: PlayerEvent.Wakeup) {
    val player = event.player
}
```

- `event.player` (Player) - текущий игрок.
- `event.wakeImmediately` (Boolean) - будет ли анимация или мгновенное вставание. (если `false`, воспроизводится анимация, при которой экран плавно возвращается из темноты в обычный режим)
- `event.updateLevelForSleepingPlayers` (Boolean) - указывает, нужно ли уведомить сервер о том, что количество спящих игроков изменилось. Если `true`, сервер пересчитывает таймер пропуска ночи, проверяя, сколько игроков осталось в кроватях.

### Взаимодействует с сущностью

*Это событие можно отменить (`event.isCanceled = true`).*

```kotlin
@SubscribeEvent
fun onPlayerInteract(event: PlayerInteractEvent.EntityInteract) {
    val player = event.player
}
```

- `event.player` (Player) - текущий игрок.
- `event.hand` (InteractionHand) - рука, которой игрок взаимодействует.
- `event.entity` (Entity) - сущность, с которой игрок взаимодействует.

:::advice
Это событие обычно при одном взаимодействии срабатывает 4 раза:
- левая рука на сервере
- левая рука на клиенте
- правая рука на сервере
- правая рука на клиенте
То есть чаще всего вам нужно сделать дополнительную проверку:
```kotlin
if (event.hand == InteractionHand.MAIN_HAND && !event.player.level().isClientSide) {
   // Уже действие, которое сработает 1 раз
}
```
:::

### Взаимодействует с блоком

*Это событие можно отменить (`event.isCanceled = true`).*


- `event.state` (BlockHitResult) - результат нажатия по блоку (содержит блок, его координаты и другую информацию).

:::advice
Это событие обычно при одном взаимодействии срабатывает 4 раза:

- правая рука на сервере
- правая рука на клиенте

```kotlin
if (event.hand == InteractionHand.MAIN_HAND && !event.player.level().isClientSide) {
   // Уже действие, которое сработает 1 раз
}
```
:::

### Пишет в чат

*Это событие можно отменить (`event.isCanceled = true`).*

```kotlin
@SubscribeEvent
fun onPlayerMessage(event: ServerChatEvent) {
    val player = event.player
}
```

- `event.player` (Player) - текущий игрок.
- `event.message` (Component) - сообщение игрока.
- `event.username` (String) - имя игрока.

:::advice
Поскольку это событие можно отменить, оно срабатывает раньше отправки сообщения. Поэтому при ответах лучше добавляйте задержку:
```kotlin
npc.say("Что думаешь?")
val text = ServerChatEvent.await().message.string
wait(1) // Ждём 1 тик, чтобы сообщение отправилось, иначе далее нпс ответит раньше игрока
npc.say("Значит твой окончательный выбор - '$text'?")
```
:::

### Выбрасывает предмет

*Это событие можно отменить (`event.isCanceled = true`).*

```kotlin
@SubscribeEvent
fun onDropItem(event: ItemEntityEvent.Toss) {
    val player = event.player
}
```

- `event.player` (Player) - текущий игрок.
- `event.entity` (ItemEntity) - выброшенный предмет (как сущность).

### Натягивает лук

```kotlin
@SubscribeEvent
fun onNock(event: ArrowEvent.Nock) {
    val player = event.player
}
```

- `event.player` (Player) - текущий игрок.
- `event.level` (Level) - текущий мир.
- `event.stack` (ItemStack) - используемый предмет.
- `event.usedHand` (InteractionHand) - используемая рука.
- `event.hasAmmo` (Boolean) - есть ли патроны / стрелы.

### Выпускает стрелу

*Это событие можно отменить (`event.isCanceled = true`).*

```kotlin
@SubscribeEvent
fun onLoose(event: ArrowEvent.Loose) {
    val player = event.player
}
```

- `event.player` (Player) - текущий игрок.
- `event.level` (Level) - текущий мир.
- `event.stack` (ItemStack) - используемый предмет.
- `event.charge` (Int) - сила натяжения (можно изменить, например умножить `x2`, чтобы ускорить лук).
- `event.hasAmmo` (Boolean) - есть ли патроны / стрелы.

## Трекинг сущностей

Эти события срабатывают, когда игрок начинает отслеживать определённых сущностей, то есть прогружает чанки с ними.

### Начинает отслеживать

```kotlin
@SubscribeEvent
fun onStartTracking(event: EntityTrackingEvent.Start) {
    event.player.send("Где-то рядом есть - ${event.entity.name.string}")
}
```

- `event.player` (ServerPlayer) - текущий игрок.
- `event.entity` (Entity) - отслеживаемая сущность.

### Прекращает отслеживать

```kotlin
@SubscribeEvent
fun onStopTracking(event: EntityTrackingEvent.Stop) {
    event.player.send("Где-то пропал ${event.entity.name.string}")
}
```

- `event.player` (ServerPlayer) - текущий игрок.
- `event.entity` (Entity) - отслеживаемая сущность.
