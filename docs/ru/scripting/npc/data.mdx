<center><h1>Пользовательские данные</h1></center>

*Дай NPC, игроку или любой сущности собственные типизированные, сохраняемые данные, без работы с сырыми NBT-тегами.*

![NPC](/docs/title-missing.webp)

## `.data`: данные, принадлежащие самой сущности

У каждой сущности есть `.data` - небольшое хранилище, которое автоматически сохраняется и восстанавливается вместе с её владельцем, навсегда, независимо от того, какой скрипт, стейт или обработчик сейчас выполняется. Это работает и на `npc`, и на `player`, и на любой другой `Entity`. Это подходящее место для репутации, ассортимента магазина или "уже встречался ли этот NPC с игроком".

Сначала объяви ключ, один раз, в начале скрипта или в отдельном импортируемом скрипте:

```kotlin
val REPUTATION = dataKey<Int>("reputation") { 0 } // 0, значение по умолчанию, если ещё не задано
```

Затем используй его где угодно, где есть сущность:

```kotlin
val current = npc.data[REPUTATION]                // Возвращает Int? (null только если нет значения по умолчанию и оно ещё не задано)
val current2 = npc.data.getOrPut(REPUTATION)      // Возвращает Int (возвращает значение по умолчанию и сохраняет его)
npc.data[REPUTATION] = current2 + 1
npc.data.update(REPUTATION) { it + 1 }            // прочитать-изменить-записать одним вызовом
REPUTATION in npc.data                            // Возвращает Boolean
npc.data.remove(REPUTATION)                       // Возвращает `true` если значение существовало
```

`dataKey<T>(name)` работает из коробки для `Int`, `String`, `Boolean` и других простых типов.

Те же вызовы работают и на игроке:

```kotlin
val VISITS = dataKey<Int>("visits") { 0 }

player.data.update(VISITS) { it + 1 }
```

:::advice
Поскольку `.data` прикреплён к самой сущности, он работает откуда угодно: из сцены `@State`, из обработчика `onInteract`/`onHurt` в [node-скрипте, прикреплённом к сущности](/docs/hollowengine/scripting/node), или из обычного обработчика события в `.reload.kts`. Ему не нужен запущенный сюжет или активный `@State`.
:::

## Сохранение и время жизни

`.data` сохраняется вместе с остальным состоянием сущности, поэтому следует за своим владельцем так же, как и другое состояние движка, привязанное к сущности:

- У обычной сущности (NPC, моб, что угодно) он записывается на диск вместе с сущностью и загружается обратно вместе с чанком.
- Он переживает смену измерения, включая портал или возврат из энда.
- У игрока он также переживает смерть: данные, записанные до `PlayerEvent.Clone`, остаются на месте у объекта игрока после респавна, копировать их вручную не нужно.

Сущность, которая ни разу не обращалась к своим `.data`, не хранит для этого никакой структуры и ничего не добавляет в свой NBT при сохранении, поэтому большинство мобов в мире, которые никогда не читают и не пишут `.data`, не платят за это ничего лишнего.

## Аналог на уровне стейта: `stateGet` / `stateSet`

В разделе [Стейты и корутины](/docs/hollowengine/scripting/node/states) уже был описан `stateTag()` - сырой NBT-контейнер, привязанный к *текущему выполняющемуся стейту*. Та же идея `DataKey` работает и там, как типизированное сокращение вместо ручного вызова `tag.putInt(...)` / `tag.getInt(...)`:

```kotlin
val VISITS = dataKey<Int>("visits") { 0 }

@State
suspend fun main() {
    val visits = stateGetOrPut(VISITS)
    stateSet(VISITS, visits + 1)

    if (visits == 0) {
        npc.say("Мы раньше не встречались!")
    }
}
```

`stateGet`, `stateGetOrPut`, `stateSet`, `stateUpdate`, `stateContains` и `stateRemove` один в один повторяют функции `.data` выше, только читают и пишут `stateTag()` вместо собственного хранилища сущности. Вызывать их нужно из `suspend`-функции, выполняющейся внутри `@State`, точно так же, как и сам `stateTag()`.

## Что где хранить?

| Хранилище | Время жизни | Нужен ли активный `@State`? |
|-----------|-------------|-------------------------------|
| `.data` (`npc.data`, `player.data`, ...) | Живёт вместе с сущностью вечно, в том числе после смерти (у игроков) и смены измерения. | Нет, работает откуда угодно. |
| `stateGet` / `stateSet` / `stateTag()` | Живёт вместе с текущим стейтом и очищается или заменяется по правилам из [Стейтов и корутин](/docs/hollowengine/scripting/node/states#сохраняем-данные-стейта). | Да. |
| `onSave` / `onLoad` у [node-скрипта](/docs/hollowengine/scripting/node) | Живёт вместе с конкретным прикреплением этого node-скрипта. | Нет, у него совсем отдельный жизненный цикл. |

Практическое правило: если данные описывают саму сущность (репутация, знакомые игроки, открытые ветки диалога) - используй `.data`. Если данные описывают прогресс по конкретной сцене или шагу квеста - используй `stateTag()` / `stateGet` / `stateSet`.
